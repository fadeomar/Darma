## القرار والنطاق

اعتمد المستخدم تصور عرض التحكم ثم النتيجة وطلب التنفيذ والدمج إلى `main`.
المرجع البصري: صورتا صفحة `/tools/qr-code` المرفقتان بتاريخ 2026-11-16 والتصور المعتمد في المحادثة؛ تعذرت قراءة الصفحة عبر أداة الويب.

- تفعيل `layout="stacked"` لصفحة QR فقط؛ الافتراضي للأدوات الأخرى يبقى `columns`.
- إزالة التمرير الداخلي وشفرة نقل التركيز المرتبطة به.
- عرض الأنواع العشرة بأيقونة وعنوان، والحقول مباشرة بعدها.
- وضع مثال مناسب للنوع بجانب الحقول، وجميع Quick starts ضمن قائمة صغيرة.
- طي إعدادات المظهر والاعتمادية افتراضيًا وتقليل حجم المعاينة وتوحيد مجموعة أزرار PNG/SVG.
- الحفاظ على منطق payload والتحقق والتوليد المحلي والتصدير، مع إظهار متطلبات النوع قرب الإدخال.

## التحقق

- اختبارات `qr.test.ts` و`studio.test.ts`: نجح 31 اختبارًا.
- `npm run typecheck`: نجح.
- `npm run lint`: نجح دون أخطاء؛ 80 تحذيرًا خارج الملفات المعدلة.
- SSR smoke: نجح؛ الأنواع العشرة، ترتيب التحكم قبل النتيجة والحقول قبل القوالب، غياب التمرير الداخلي لـQR وبقاؤه في layout الافتراضي.
- `git diff --check`: نجح.
- `npx prisma generate` ثم `npx next build --webpack`: نجح البناء (exit 0). ظهرت رسائل لصفحات أخرى عن غياب `DATABASE_URL` وفشل تحميل بعض الرموز في خطوط OG؛ لا يتطلب QR قاعدة بيانات.
- lint للملفين المعدلين: نجح بلا تحذيرات.
- اختبار متصفح تفاعلي وقياس التصميم على desktop/mobile: لم ينفذا؛ Chromium لا يستطيع إنشاء socket في البيئة الحالية. لا تعتبر فحوصات SSR دليلًا على التشغيل التفاعلي أو المسح بالكاميرا.
