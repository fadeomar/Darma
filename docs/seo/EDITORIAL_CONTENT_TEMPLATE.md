# Darma Editorial Content Template

Use this template for every indexable guide, comparison, or resource hub. The goal is to answer a real search need while giving readers practical value that cannot be obtained from a list of links alone.

## 1. Search intent

Record before drafting:

- Primary query and close variants
- Reader level and likely context
- Decision, task, or confusion the page must resolve
- Existing Darma entities that should support the answer
- Primary official or first-party references
- What original value Darma will add

Do not create a page merely because a keyword exists. Create it when Darma can answer the intent completely and connect it to useful actions.

## 2. Required page structure

1. **Clear H1** matching the topic naturally.
2. **Direct answer** that resolves the core question near the beginning.
3. **Key takeaways** for readers who need a fast decision.
4. **Detailed sections** that explain reasoning, tradeoffs, workflow, or progression.
5. **Practical evidence**, such as a project, checklist, decision framework, example, or comparison table.
6. **When to use / when not to use** where the topic involves a choice.
7. **Common mistakes or misconceptions.**
8. **Related Darma learning paths, careers, workflows, glossary terms, and resources.**
9. **Frequently asked questions** based on real follow-up intent.
10. **Primary references**, author, reviewer, published date, and last-reviewed date.

## 3. Editorial quality rules

- Prefer official documentation and first-party standards.
- Explain why a recommendation fits a context; do not declare universal winners.
- Do not copy or closely paraphrase reference material.
- Separate verified facts from Darma editorial judgment.
- Use meaningful examples and named deliverables.
- Avoid artificial word-count expansion, repeated introductions, and keyword stuffing.
- Never mark a source as official, free, current, or verified without evidence.
- Update the review date only after a real content review.
- Preserve accessibility: descriptive headings, link text, tables, and image alternatives.

## 4. Guide-specific requirements

A guide should include:

- Who the guide is for
- Prerequisites
- A sensible sequence
- Checkpoints or evidence of learning
- At least one practical project or application
- What to learn later rather than immediately
- Next paths or roles

## 5. Comparison-specific requirements

A comparison should include:

- A concise verdict that states the decision context
- A side-by-side table using comparable criteria
- Strengths, constraints, and maintenance implications
- A repeatable evaluation method
- Scenarios in which each option is a reasonable choice
- A warning when titles or implementations vary by organization

## 6. Resource-hub requirements

A resource hub should include:

- A short explanation of the topic
- A curated set rather than every matching link
- Why each source is useful
- Official and community status
- Level, type, and review status when known
- Related paths, careers, and guides

## 7. Review checklist

Before merge:

- [ ] Search intent is answered directly.
- [ ] The page adds original practical value.
- [ ] Claims are supported by appropriate references.
- [ ] Internal links resolve to existing entities.
- [ ] Metadata title and description are unique.
- [ ] Canonical URL is correct.
- [ ] Structured data matches visible content.
- [ ] Author, reviewer, publication date, and review date are present.
- [ ] Mobile layout and keyboard navigation were checked.
- [ ] `npm run seo:authority` passes.
